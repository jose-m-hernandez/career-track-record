## 1. Purpose

A tailored draft is compared with its parent by readers. Today a run can print SUPPORTED for a margin of two pairs while the same readers, shown identical drafts, picked a side in two pairs of their own. The A/A arm already runs in every run (`reader-ab.md:250`) and already gates the run as a whole (`reader-ab.md:162`). This revision lets a plan that asks for it have the same arm also say, per hypothesis, that a SUPPORTED margin is no larger than what identical drafts produced, and say so as a verdict, not as a footnote.

The band comes only from the A/A arm of this run, or pooled through `aa-pool` (`reader-ab.md:65`, `:162`). It is never a number written in the plan and never a number from anyone's records.

## 2. Definitions

All counts use blind readers only (`reader-ab.md:153`, `:157`).

1. **A/A pair.** The A/A arm's reads of one reader, taken two at a time in read order: its first and second read, its third and fourth, and so on. This is the pairing every other arm already has (`reader-ab.md:97`; `ab.py:1510-1527`, which pairs every arm's reads). The A/A arm stays unpaired for its gate, which keeps counting single reads (`reader-ab.md:160`, `:162`; `ab.py:1628-1636`).
2. **An A/A pair picks a side** when both of its reads are non-TIE, at any strength, and they name different slots. That is the slot pattern of a comparison pick: a comparison pair puts each version in slot A once (`reader-ab.md:97`), so a pick for one version names slot A in one read and slot B in the other, and two reads that name the same slot are an order-split pair, a TIE (`reader-ab.md:160`; 10.3). Two reads of identical drafts that name the same slot show a slot preference, which position reports (`reader-ab.md:163`); they do not pick a side here either. A pair with a TIE read does not pick a side. A pair with a failed read is not valid.
   *Build note, not signed text:* the shipped pair rule cannot be reused for this. On the A/A arm both slots hold one version, so `pair_pick` returns that version for two same-slot reads (`ab.py:1466-1474`, `:1540-1545`; measured at `cc6b1c9`: two `prefer slot A` A/A reads give `pair_pick` = the version). The band tests the two reads' slot letters (`A` against `B`, `ab.py:1466-1474`), not the version they map to. The shipped comparison arm is not affected: there the two reads map to different versions, so a same-slot pair is already a TIE (`ab.py:1540-1545`; 10.3).
3. **A/A side count `k` and pair count `n`.** `k` is the number of valid A/A pairs that pick a side; `n` is the number of valid A/A pairs. With `aa-pool`, both include each pooled run's valid blind A/A pairs, each formed inside its own run and never across runs (`ab.py:1510-1512`). In an extension (`reader-ab.md:85`), both include the first run's A/A pairs, as the gate's reads do (`ab.py:2047`).
4. **The band is evaluated** when the A/A gate is evaluated, that is, when at least one A/A read is planned and every planned blind A/A read is valid, this run's, the pool's and the first run's (`reader-ab.md:162`; `ab.py:1628-1633`, which returns "not evaluated" for zero planned reads). Then `n >= 1`: the pooled gate is evaluated only with valid blind A/A reads, and one pair exists for every two valid blind reads of a reader (the even `reads-per-reader` of 2 or more, `reader-ab.md:559`, `:585`, `:388`; `ab.py:408-413`, refuses an odd count at freeze). `P` is the number of planned blind pairs of *this* plan, and it can still be 0: an `aa-pool` may supply blind pairs (compatibility compares reader commands, `ab.py:1090`, while blindness is read from each run, `:1794-1813`) while this plan marks every reader `not-blind`. The band is calculated only when `n >= 1` and `P >= 1`; `P = 0` suppresses the band, nothing is calculated and no band line is printed. Otherwise there is no band, and `ceil(k * P / n)` is not calculated: a plan whose readers are all `not-blind` has no planned blind pair (`ab.py:832-838`), and nothing divides by zero.
5. **Band `b`**, in paired picks of a comparison arm: `ceil(k * P / n)`, where `P` is the number of planned blind pairs of the comparison arm, pooled with the first run's in an extension (every comparison arm has the same `P`: they share `reads-per-reader` and readers). Without a pool and without an extension `n = P`, so `b = k`. With a pool, `n` is larger than `P`, and the count is scaled to the arm's size by its share, rounded up, as the family rule rounds its shares (`reader-ab.md:167`).
6. **Margin `m`** of a hypothesis: the number of paired picks for the version its deciding clause names, minus the number of paired picks for the comparison's other version. TIE pairs are in neither. `m` can be zero or negative (a rule can hold while the other version leads, for example `SUPPORTED if Y preferred in 2 or more` with two picks for `Y` and three for `X`).

## 2a. Words

On a read or a pair, TIE is a pick value (`reader-ab.md:160`). With `aa-band: on` it is also a verdict. The verdict TIE is printed only on a `hypothesis <h> verdict:` line, in the TIE line of § 4, and in the series row's `result` cell, where it is written `h<n> TIE` (series spec § 5); every count line (`pair counts`, `evidence`, `order consistency`) keeps counting TIE reads and pairs as before and never uses the word for a verdict. A plan without the key never prints the verdict TIE.

## 3. The plan key and the rule

**The key.** `aa-band` (optional, a scalar): the only value is `on`. Any other value, or an empty one, is refused at freeze, exit `2`, naming the plan line, and writes no freeze file. Without the key nothing in this spec applies. The key is part of the plan and so of the plan's hash: a change to it after the freeze is refused as any plan edit is (`reader-ab.md:82`). (`aa-band` is the working name.)

- **Amendment.** `aa-band` joins the settings an amendment may not change (`ab.py:822-825`, compared at `ab.py:898-900`): `freeze` refuses it, exit `2`, with `an amendment may not change aa-band from the plan it amends`, whether the key is added, dropped or changed.
- **Extension.** Already refused: an extension may differ from its first run in sample size only, and every other key, one the first plan lacks included, is compared (`ab.py:1005-1015`), so the message is the shipped `an extension may change only reads-per-reader and the number of readers of each model: aa-band`.
- **Replicate.** Byte-identical to the first plan apart from `replicate-of` (`reader-ab.md:86`), so it carries the same key or none.
- **`aa-pool`.** A pooled run need not carry the key: it contributes A/A reads and pairs, never a verdict (`reader-ab.md:162`).
- **An older tool** reading a plan with the key refuses it as an unknown key, exit `2` (`reader-ab.md:52`), so a plan that asks for the band is never scored without it.

**The rule.** With the key, after the family rule has run, on the verdict as it then stands (`ab.py:1705-1709`, so a lifted verdict is included): **if the verdict is SUPPORTED, the band is evaluated, and `m <= b`, the verdict is `TIE`.** Equal is inside the band.

- **Precedence.** SUPPORTED becomes TIE; nothing else changes. REFUTED, INCONCLUSIVE and every reason line are as in revision 4. A hypothesis that revision 4 reports INCONCLUSIVE for a gate, position, the read floor or the family rule stays INCONCLUSIVE and gets no TIE line.
- **No band, no TIE.** When the band is not evaluated, no verdict is TIE and no band line is printed. Because every comparison is INCONCLUSIVE when the A/A gate is not evaluated (`reader-ab.md:162`), that state never holds a SUPPORTED verdict to change. (A plan has no way to omit the A/A arm: the tool adds one, `reader-ab.md:57`, `:250`.)
- **Not-blind reads** are in neither the band nor the margin (`reader-ab.md:153`).
- **Second reading.** The second reading (`reader-ab.md:166`) is unchanged and applies no band. When the verdict is TIE, the second reading's verdict is printed beside it as it is for an INCONCLUSIVE verdict, with no "holds only one way" sentence (`reader-ab.md:166`, `:213`).
- **Completions and the lift** read the rule alone (`reader-ab.md:180`) and do not apply the band. A lift that makes a verdict SUPPORTED is followed by the band test like any SUPPORTED.
- **The disagreement flag** (`reader-ab.md:179`) is not printed for a TIE verdict, as it is not printed for the other reasons listed there; the TIE line says why.
- **Mechanisms, scores, position and sensitivity** are unchanged; the band never touches a mechanism verdict.
- **Known limit.** `k` is one observed count over a few pairs (6 with the default plan). The band is a bar a margin must clear, not a test: a run whose margin clears it has not been shown to differ from chance, and the p-value line of § 6.1 stays beside it. The band tests SUPPORTED only. A REFUTED verdict is not tested against it and prints no margin line, so a REFUTED whose margin is inside the band is still printed REFUTED; read it with the `A/A band` line beside it. With the default noise threshold of `1/2` a plan that passes the A/A gate has `k` of at most 2 of 6 pairs (a side-picking pair needs two non-TIE reads, and six non-TIE reads of 12 trip the gate), so on a default plan the band is 0, 1 or 2 pairs.

## 4. Printed lines

Only for a plan with `aa-band: on`; a plan without it prints no line of this section.

- Once per run, after the `A/A gate interval` line, when the band is evaluated: `A/A band: identical drafts picked a side in <k> of <n> valid A/A pairs; band <b> pairs`. When the band is not evaluated no band line is printed.
- For each hypothesis whose verdict was SUPPORTED when the band was tested, on the line after its `second reading` line and before its `family` lines: `hypothesis <h> margin: <m> pairs (<Y> <a> picks, <X> <c> picks) against band <b> pairs`, where `<Y>` is the version the deciding clause names and `<X>` the other.
- When the verdict becomes TIE, the verdict line is `hypothesis <h> verdict: TIE [not blind: <b> reads left out]`, and the next line is: `TIE: <h>: the margin of <m> pairs is inside this run's A/A band (identical drafts picked a side in <k> of <n> pairs). The versions are not shown to differ.` (`<h>` is the hypothesis name; `<m>` is a signed integer, `-1` included.) The `hypothesis <h> reason:` lines of revision 4 are not used for TIE.
- `validity:` and every other line are as in revision 4.

The result file carries every line above, as it carries every other line (`reader-ab.md:224-235`).

## 5. Exit status

Unchanged: a TIE is a verdict, and a completed run exits `0` whatever its verdicts (`reader-ab.md:241`).

## 6. Rules that hold in every run

Revision 4's list (`reader-ab.md:249-258`) stands, and gains: **a verdict of TIE is given only to a plan that names `aa-band: on`, and only against an A/A band measured in the same run, the pool its plan names, or the first run of its extension; no setting, plan key or option supplies a band's number.**

## 7. Plans and freeze files from earlier releases: an exception to the signed rule

`reader-ab.md:87` says a plan frozen under an earlier revision is never scored under the later revision's rules, and `:253` says a plan is scored only under the revision that froze it. Revision 4 could tell an earlier freeze by a missing key; a revision-4 freeze file and a revision-5 freeze file of a plan with no `aa-band` line are byte for byte alike, so nothing in a freeze file says which revision made it, and this spec adds no marker.

**The exception, stated plainly.** A plan with no `aa-band` key is run and scored by revision 5 under revision 4's rules, whichever revision froze it. This does not honour `:87` and `:253`; it departs from them, and is permitted only because, with no `aa-band` key, revision 5 gives the result revision 4 gives, line for line (case T17, and every revision-4 acceptance test of `reader-ab.md` § 10, 10.1 to 10.94, passing unchanged at revision 5; a `series` key adds only its own lines and writes, series-row spec § 5, and changes no verdict), so no verdict changes because the tool was upgraded. A plan with the key is not an exception: an older tool refuses the key (§ 3), so it can only be scored by a release that knows it. `freeze` writes the same freeze file as before.

## 9. Does it change existing plans' verdicts?

No. A plan without `aa-band: on` reads as in revision 4, byte for byte in its result, and no freeze file is refused (§ 7). For a plan that names the key: a SUPPORTED verdict whose margin is inside the band becomes TIE (§ 3), and the result gains the lines of § 4. A plan whose A/A arm gave every read TIE (band 0) changes only if its SUPPORTED margin is 0 or negative.

Correction: T16 is built as follows, and the signed inputs cannot occur.

Why the signed inputs cannot occur. T16 as signed has the extension's A/A arm all TIE while the first run's A/A reads 1 to 4 alternate slots, giving a pooled `k` of 2 of 12. An extension may differ from its first run in sample size only, so it must carry its first run's `fake-reader` lines text for text (`ab.py` `extension_problems`, which compares every key but `reads-per-reader`, `readers` and `extends`; `reader-ab.md:85`; TIE spec § 3 "Extension"). A fake rule names a read number, and A/A pairs are reads 1-2, 3-4 and so on in every run (§ 2 definition 1), so the extension's A/A reads 1 to 4 follow the same rules as the first run's: the extension's A/A arm cannot be all TIE, and no fixture avoids it (a rule on a read beyond the smaller run's reads is refused at parse, and the pair boundaries never move because `reads-per-reader` is even). Pooled `k` is 4 of 12, not 2.
